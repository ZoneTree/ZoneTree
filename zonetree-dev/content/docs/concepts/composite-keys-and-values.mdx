Both live in the `ZoneTree.Composite` namespace and produce plain byte arrays. A tree of `byte[]` keys sorts composite keys with its built-in lexicographic comparer, so nothing has to be registered.

| | `CompositeKey` | `CompositeValue` |
| --- | --- | --- |
| Use it for | Keys: rows, index entries, key ranges | Values: rows of several fields, index entries that carry fields |
| Order | Bytes sort element by element; elements can be descending | None |
| Reading one element | Walks the elements before it | Direct, from the header |
| Strings and bytes | Zero bytes escaped, so they sort | Stored as they are |
| Round trip | One encoding per value: `1.0m` and `1.00m` are one key | Exact: a decimal keeps its scale, a `DateTime` its kind |
| Changing one element | Build the key again | `With` and `Append` copy the other elements as they are |

## Keep rows and indexes in one tree

A leading element can name what a key holds. One tree then keeps rows and the entries of several indexes, each in a key range of its own, and an index entry ends with the elements of its row's key. This console example writes an order with two index entries, then reads every order of one customer:

```csharp
using ZoneTree;
using ZoneTree.Comparers;
using ZoneTree.Composite;

using var tree = new ZoneTreeFactory<byte[], byte[]>()
    .SetDataDirectory("data/composite-orders")
    .OpenOrCreate();
using var maintainer = tree.CreateMaintainer();

var placed = new DateTime(2026, 11, 15, 9, 30, 0, DateTimeKind.Utc);
tree.Upsert(CompositeKey.Create("row", 42L), CompositeValue.Create("bob", 19.99m, placed));
tree.Upsert(CompositeKey.Create("by-customer", "bob", 42L), CompositeValue.Create(19.99m));
tree.Upsert(CompositeKey.Create("by-time", CompositeKey.Descending(placed), 42L), CompositeValue.Create(19.99m));

var (from, to) = CompositeKey.Range(CompositeKey.Create("by-customer", "bob"));
var order = new BytesLexicographicComparerAscending();
using var iterator = tree.CreateIterator();
iterator.Seek(from);
while (iterator.Next() && order.Compare(iterator.CurrentKey, to) <= 0)
{
    var id = CompositeKey.Get<long>(iterator.CurrentKey, 2);
    var total = CompositeValue.Get<decimal>(iterator.CurrentValue, 0);
    Console.WriteLine($"{id}: {total}");
}
```

It prints `42: 19.99`. The application writes the index entries along with their row, and a [transaction](../usage/transactions.mdx) keeps them together. An empty byte array is a deletion, so an index entry needs a value of at least one byte; a `CompositeValue` is never empty, and it can carry the fields a query reads.

## Bound a scan with Range or BeginsWith

Both return inclusive `From` and `To` bounds for a seek and a scan in byte order:

| Function | Holds | Use it for |
| --- | --- | --- |
| `Range(prefix)` | The keys under whole elements: the prefix itself, and every key that goes on from it with more elements | Lookups by leading elements: every order of the customer `"bob"` |
| `BeginsWith(prefix, text)` | The keys whose next element, after the prefix, is a string that begins with the text | Search as the user types: every name that begins with `"bo"` |

```csharp
var bob = CompositeKey.Range(CompositeKey.Create("by-name", "bob"));
// holds ("by-name", "bob") and ("by-name", "bob", 42), not ("by-name", "bobby")

var bo = CompositeKey.BeginsWith(CompositeKey.Create("by-name"), "bo");
// holds ("by-name", "bo"), ("by-name", "bob", 42) and ("by-name", "bobby"), not ("by-name", "bp")
```

`Range` matches whole elements, so a lookup for the customer `"bob"` never returns the orders of `"bobby"`. `BeginsWith` matches text by Unicode code point, as strings sort. Its other overload takes bytes, for hash or path prefixes, and both take `CompositeKeyOrder.Descending` as a third argument for a descending element.

## Sort an element in reverse

`CompositeKey.Descending(value)` makes one element sort in reverse, so a newest-first index is `("by-time", Descending(placed), id)`. Other elements keep their own direction, and the element reads back as its own type: `Get<DateTime>`, not `Get<Descending<DateTime>>`. A [reverse iterator](../usage/iteration-and-range-scans.mdx), or a tree created with `BytesLexicographicComparerDescending`, reverses whole keys instead.

## Fix a key space with a layout

A key layout fixes one key space for good: the constant elements its keys start with, then the type and the order of each position. Keys made through a layout always agree on both, so the same value never becomes two keys and a layout's ranges hold exactly its keys:

```csharp
static readonly CompositeKeyLayout<string, long> ByCustomer = new(CompositeKey.Create("by-customer"));
static readonly CompositeKeyLayout<DateTime, long> ByTime = new(CompositeKey.Create("by-time"), CompositeKeyOrder.Descending);

tree.Upsert(ByTime.Create(placed, orderId), entry);  // compiles only with a DateTime and a long
var (when, id) = ByTime.Decode(key);                   // checks the prefix, the orders, and the element count

var newestFirst = ByTime.Range();                      // every key of the layout
var bobs = ByCustomer.Range("bob");                    // the keys that start with these elements
bool isOrder = ByCustomer.Matches(key);                // whether a key starts with the layout's prefix
```

A layout has a typed form for one to eight positions, and an unsupported type fails when the layout is made, not when it is first used. Making a key through a layout costs what `Create` costs, because the prefix is encoded once, when the layout is made. `Prefix` and `Order(position)` give what the layout fixed, so its first position, when it is a string, takes `BeginsWith` as well:

```csharp
var names = CompositeKey.BeginsWith(ByName.Prefix, "bo", ByName.Order(0));
```

## Join, slice, and build keys

A key is its elements one after another, with no header. Two keys joined end to end are the key of their elements together, and `ElementBytes` returns an element, or a run of elements, as a slice of the key that is itself a key:

```csharp
var row = CompositeKey.Create("row", 42L);
byte[] entry = [.. CompositeKey.Create("by-customer", "bob"), .. CompositeKey.ElementBytes(row, 1)];

// From the entry back to its row.
byte[] rowKey = [.. CompositeKey.Create("row"), .. CompositeKey.ElementBytes(entry, 2, 1)];
```

`Create` and `Decode` take up to eight elements. `CompositeKeyBuilder` builds keys of any length, and keeps its buffer for the next key after `Clear`:

```csharp
var builder = new CompositeKeyBuilder().Add("by-tags");
foreach (string tag in tags)
    builder.Add(tag);
var key = builder.Add(orderId).ToArray();
```

An element's type is the type argument of `Create`, `Add`, or `Get`, so an element passed as `object` is not supported.

| Member | Gives |
| --- | --- |
| `Decode<T1, …>(key)` | The leading elements, up to eight; elements after them are left unread |
| `Get<T>(key, index)` | One element, at any position |
| `ElementCount`, `ElementType`, `IsDescending` | The shape of a key |
| `ElementBytes(key, index)`, `ElementBytes(key, start, count)` | The encoded bytes of an element, or of a run of elements |
| `Offsets(key, offsets)` | Where every element starts, in one pass, for direct access afterwards |
| `CompositeKeyReader` | Every element in turn, without allocating, in a key of any length |
| `IsValid(key)` | Whether bytes are a well-formed composite key |

A key has no header, so reading element `i` walks the elements before it. For keys of a few elements that costs little; code that reads many elements of one key uses `Offsets` or the reader.

## How composite keys sort

- Elements compare one at a time, and a key sorts before every key that extends it.
- Elements of different types sort by type, in the order of `CompositeElementType`: null, bytes, string, integer, floating, decimal, boolean, `DateTime`, `DateTimeOffset`, `DateOnly`, `TimeOnly`, `TimeSpan`, `Guid`.
- Ascending elements sort before descending ones at the same position.
- Within a type, elements sort by value:
  - Integers compare by value whatever type wrote them: `5`, `5L`, `(byte)5`, and `(Int128)5` are the same element. An integer holds at most 255 bytes.
  - Floating values compare by value. `0.0` and `-0.0` are one element, and every NaN is one element, which sorts after positive infinity.
  - Decimals compare by value, so `1.0m` and `1.00m` are one key, which reads back as `1`.
  - A `DateTime` sorts by its ticks and reads back with an unspecified kind.
  - A `DateTimeOffset` sorts by its UTC instant: the same instant at any offset is one key, which reads back with a zero offset.
  - Strings sort by Unicode code point and must be valid UTF-16. Bytes sort lexicographically.
  - Guids sort as their text forms do.

## Composite values

```csharp
using ZoneTree.Composite;

var value = CompositeValue.Create("bob", 19.99m, placed);

var (customer, total, when) = CompositeValue.Decode<string, decimal, DateTime>(value);
var totalOnly = CompositeValue.Get<decimal>(value, 1);  // reads the header, then element 1
```

- **Direct access.** The header gives each element's type and where it ends, so `Get`, `ElementType`, and `ElementPayload` read one element without touching the others.
- **Payloads as they are.** `ElementPayload(value, index)` returns an element's payload as a slice of the value: a string's UTF-8 bytes, or the bytes of a bytes element. Binary payloads are stored without escaping, so they add no size.
- **Exact round trips.** A decimal keeps its scale, a `DateTime` its kind, and a `DateTimeOffset` its offset. A `float` stays 4 bytes and a `Half` 2, and `-0.0` stays `-0.0`.
- **Minimal integers.** An integer takes its minimal two's complement width: `0` takes no bytes and `127` takes one.
- **Growing values.** `Decode` reads the leading elements and leaves the rest unread, so a value grows by elements added at its end. `ElementCount` tells a reader whether a later element is there.
- **Never empty.** A value of no elements is two bytes, never the empty array a tree takes for a deletion.

### Change one element

`With` replaces one element of a value, and `Append` adds one at its end. Both copy every other element as it is, without decoding it, into one new array, so a partial update costs a copy of the bytes, not a decode and an encode of every field:

```csharp
var cheaper = CompositeValue.With(value, index: 1, 15.99m);  // the same customer and time
var tagged = CompositeValue.Append(value, "gift");           // a field a newer row has
```

They fit an [atomic update](../usage/atomic-operations.mdx) that changes one field of a stored row.

### Build and project values

`CompositeValueBuilder` builds values of any length. Its `AddElements` copies elements of another value as they are, which is how a projection keeps some fields of a row:

```csharp
var summary = new CompositeValueBuilder()
    .AddElements(value, start: 0, count: 2)  // the customer and the total
    .Add(itemCount)
    .ToArray();
```

`CompositeValueReader` walks the elements of a value, with each element's `ElementType` and `Payload`, and `IsValid(value)` tells whether bytes are a well-formed composite value.

## Element types

| .NET type | Element type | Notes |
| --- | --- | --- |
| `sbyte`, `byte`, `short`, `ushort`, `int`, `uint`, `long`, `ulong`, `nint`, `nuint`, `Int128`, `UInt128`, `BigInteger`, `char`, enums | Integer | Compared and read by value. An enum is its underlying value. |
| `Half`, `float`, `double` | Floating | |
| `decimal` | Decimal | |
| `bool` | Boolean | |
| `DateTime`, `DateTimeOffset`, `DateOnly`, `TimeOnly`, `TimeSpan` | One type each | |
| `Guid` | Guid | |
| `string` | String | Must be valid UTF-16. |
| `byte[]`, `Memory<byte>`, `ReadOnlyMemory<byte>` | Bytes | |
| A null string or byte array, or a nullable value type without a value | Null | Every value type above can be nullable, enums included. |
| `Descending<T>` of any type above | The type's own | Keys only. |

`Int128` and `UInt128` need .NET 7 or later.

## Reading rules

An element reads as a type that holds its value. An integer reads as any integer type that holds it, and as an enum whose underlying type holds it, named or not. A floating value reads as any floating type that holds it exactly. A null element reads as null for strings, byte arrays, and nullable value types. Every other element reads only as its own type.

| Exception | When |
| --- | --- |
| `InvalidCastException` | The element has another type |
| `OverflowException` | The type cannot hold the element's value exactly |
| `ArgumentOutOfRangeException` | No element at the index, or, in a key, an integer wider than 255 bytes |
| `ArgumentException` | The bytes are malformed, there are fewer elements than `Decode` reads, or a string is not valid UTF-16 or UTF-8 |
| `NotSupportedException` | The type is not supported, or a value is given a descending element |

The members of `CompositeKey`, `CompositeValue`, and key layouts are safe for concurrent use. A reader is a stack-only struct local to the method that creates it, and a builder is not safe for concurrent use. `Create` measures its elements first and allocates exactly one array of the right length.

## Byte formats

Both formats are fixed, so any language or tool can read and write them. A key is its elements one after another, each a tag byte and an order-preserving payload. A value is a header of element types and ends, then the payloads in little-endian bytes. The [Composite README](https://github.com/ZoneTree/ZoneTree/blob/main/src/ZoneTree/Composite/README.md#formats) gives every tag and payload.
